Version traps

You will not know the library versions in advance. Print pd.__version__ and sklearn.__version__ in your first minute.

Trap Works on every version
resample("M") and Grouper(freq="M") were renamed "ME" in pandas 2.2 df["ts"].dt.to_period("M")
mean_squared_error(..., squared=False) was removed from recent scikit-learn np.sqrt(mean_squared_error(...))
OneHotEncoder(sparse=False) became sparse_output in scikit-learn 1.2 Leave the argument out
fillna(method="ffill") is deprecated since pandas 2.1 .ffill()
df["a"][mask] = x changes nothing in pandas 3 df.loc[mask, "a"] = x

Mistakes that cost the most points

  • A join that multiplies rows. validate="m:1" raises an error if the key is not unique.
  • Leakage. Fit scalers, imputers and encoders on training rows only. A pipeline does this for you. Never build a feature from the target or from later rows.
  • Accuracy on a rare target. Report precision, recall and PR AUC.
  • Passing 0/1 predictions to roc_auc_score. It needs probabilities.
  • Treating 0.5 as the threshold for a model trained with class weights. Its scores are inflated on purpose.
  • Tuning on the test set. Choose settings by cross-validation on the training set and touch the test set once.
  • Skipping the last six minutes. A notebook that fails on a clean run can lose every later task.

    "signup_date": pd.Timestamp("2021-01-01")
                   + pd.to_timedelta(rng.integers(0, 1800, N_CUST), unit="D"),
    "segment": rng.choice(["student", "standard", "rewards", "premium"],
                          N_CUST, p=[0.15, 0.45, 0.30, 0.10]),
    "credit_limit": rng.choice([500, 1000, 2500, 5000, 10000, 20000],
                               N_CUST, p=[0.10, 0.20, 0.25, 0.25, 0.15, 0.05]).astype(float),
})

t = pd.DataFrame({
    "txn_id": np.arange(1, N_TXN + 1),
    "customer_id": rng.choice(customers["customer_id"].to_numpy(), N_TXN),
    "ts": pd.Timestamp("2026-01-01")
          + pd.to_timedelta(rng.integers(0, 181 * 24 * 3600, N_TXN), unit="s"),
    "amount": np.round(rng.lognormal(3.6, 1.0, N_TXN), 2),
    "category": rng.choice(
        ["grocery", "dining", "gas", "travel", "electronics", "jewelry"],
        N_TXN, p=[0.30, 0.25, 0.15, 0.10, 0.15, 0.05]),
    "channel": rng.choice(["online", "in_store"], N_TXN, p=[0.35, 0.65]),
})

# fraud depends on things you can observe at the time of the transaction
m = t.merge(customers, on="customer_id")
age_days = (m["ts"] - m["signup_date"]).dt.days
z = (-6.6
     + 1.5 * (m["channel"] == "online")
     + 1.2 * (m["ts"].dt.hour < 5)
     + 1.0 * np.log(m["amount"] / 50).clip(-2, 4)
     + 1.3 * m["category"].isin(["electronics", "jewelry"])
     + 0.9 * (age_days < 120)
     + 1.0 * ((m["channel"] == "online") & (m["ts"].dt.hour < 5))
     + 0.9 * (m["amount"] / m["credit_limit"] > 0.25))
t["is_fraud"] = (rng.random(N_TXN) < 1 / (1 + np.exp(-z))).astype(int)

# make it messy, the way real extracts are
orphans = rng.choice(N_TXN, 300, replace=False)

t.loc[rng.random(N_TXN) < 0.02, "category"] = np.nan

import numpy as np
import pandas as pd


def load_clean():
    cust = pd.read_csv("customers.csv", parse_dates=["signup_date"])
    txn = pd.read_csv("transactions.csv", parse_dates=["ts"])

    txn = txn.drop_duplicates().copy()
    txn["amount"] = (txn["amount"].astype(str)
                                  .str.replace(r"[$,]", "", regex=True)
                                  .astype(float))
    txn["category"] = txn["category"].fillna("unknown")

    cust["segment"] = cust["segment"].str.strip().str.lower()
    seg_median = cust.groupby("segment")["credit_limit"].transform("median")
    cust["credit_limit"] = cust["credit_limit"].fillna(seg_median)
    return cust, txn


cust, txn = load_clean()

print((~txn["customer_id"].isin(cust["customer_id"])).sum())   # (b)

                             precision_score, recall_score, roc_auc_score)

# (a) rank quality of both models
for name, p in [("logistic", p_logit), ("boosting", p_boost)]:
    print(name, round(roc_auc_score(y_test, p), 3),
          round(average_precision_score(y_test, p), 3))

p = p_logit                       # the better model on PR AUC

# (b) behaviour at the default threshold
pred = (p >= 0.5).astype(int)
print(confusion_matrix(y_test, pred))          # [[TN, FP], [FN, TP]]
print(round(precision_score(y_test, pred), 3),
      round(recall_score(y_test, pred), 3),
      round(f1_score(y_test, pred), 3))

# (c) best precision with recall of at least 0.70
prec, rec, thr = precision_recall_curve(y_test, p)
ok = rec[:-1] >= 0.70             # thr is one element shorter than prec and rec
best = np.argmax(np.where(ok, prec[:-1], -1))
print(round(thr[best], 3), round(prec[best], 3), round(rec[best], 3))

# (d) threshold with the lowest dollar cost
amount, y = test["amount"].to_numpy(), y_test.to_numpy()
rows = []
for th in np.arange(0.05, 0.96, 0.05):
    flag = p >= th
    missed = amount[(y == 1) & ~flag].sum()
    false_alarms = ((y == 0) & flag).sum()
    rows.append((round(th, 2), round(missed + 4 * false_alarms, 2)))
cost = pd.DataFrame(rows, columns=["threshold", "total_cost"])
print(cost.sort_values("total_cost").head(3))
print(round(amount[y == 1].sum(), 2))          # cost of flagging nothing

Diagonal reading order

Write diagonal_order(grid). Read a rectangular grid along its anti-diagonals, starting at the top-left cell and alternating direction: the first diagonal upward, the next downward, and so on.

Show solutionHide solution
python
def diagonal_order(grid):
    if not grid or not grid[0]:
        return []
    rows, cols = len(grid), len(grid[0])
    out = []
    for d in range(rows + cols - 1):
        cells = [grid[r][d - r]
                 for r in range(max(0, d - cols + 1), min(rows, d + 1))]
        out.extend(cells[::-1] if d % 2 == 0 else cells)
    return out

The whole problem is index bookkeeping. Cells on diagonal d satisfy row + column = d, and the row runs from max(0, d − cols + 1) to min(rows − 1, d). Test a grid that is not square before you submit: [[1, 2, 3, 4], [5, 6, 7, 8]] gives [1, 2, 5, 6, 3, 4, 7, 8].

from collections import Counter


def count_pairs(amounts, k):
    seen = Counter()
    pairs = 0
    for a in amounts:
        r = a % k
        pairs += seen[(k - r) % k]
        seen[r] += 1
    return pairs

Two numbers sum to a multiple of k when their remainders add up to k, or both are 0. Keep a count of the remainders seen so far and look up the one that completes each new value. That is one pass in place of 5 billion comparisons. The % k on the complement handles remainder 0.

ST 01Role play

Explain a p-value to a product manager who has never taken statistics.

Show answerHide answer

Suppose the new page really made no difference. The p-value answers one question: how often would luck alone produce a gap at least as big as the one we saw? A p-value of 0.03 means about 3 times in 100.

  • A small p-value makes the “no difference” story hard to believe, so we act as if the change is real.
  • It is not the probability that the change does nothing, and it says nothing about how big the effect is.
  • Pair it with the size of the effect and a range: “sign-ups rose 0.6 points, give or take 0.6”.
  • End with the decision it supports. A business partner wants to know what to do, not the definition.

ST 04Technical

What is the bias-variance trade-off? How do you tell which problem a model has?

Show answerHide answer

Expected error on new data = bias² + variance + noise you cannot remove.

  • Bias: the model is too simple for the pattern, like a straight line through a curve.
  • Variance: the model chases quirks of the training sample, like an unpruned tree.
What you see Diagnosis What to try
Training error high, validation error about the same High bias More features or interactions, a more flexible model, less regularization
Training error low, validation error much higher High variance More data, a simpler model, more regularization, bagging, early stopping

Bagging (random forest) mainly cuts variance. Boosting mainly cuts bias.

ST 06Technical · Case

For a fraud model, which matters more: precision or recall?

Show answerHide answer

It depends on what each mistake costs, so put a dollar figure on both.

  • A missed fraud costs roughly the transaction amount, plus handling.
  • A false alarm costs a declined purchase, a support contact, and some chance the customer stops using the card.

Pick the threshold that minimizes total expected cost. Case BC 02 works through one. Two refinements:

  • Expected loss is probability × amount, so large transactions deserve a lower threshold.
  • Scores in the middle can trigger a text message check in place of a decline, which makes false alarms cheap.

A credit approval model follows the same logic with different costs. Approving someone who defaults loses the balance. Declining a good customer loses years of profit.

ST 07Technical

ROC AUC or PR AUC: which do you report for a rare-event model, and why?

Show answerHide answer

Both, and lead with PR AUC (average precision).

  • ROC AUC is the chance that a random positive is scored above a random negative. It ignores class balance. With rare positives the false positive rate has a huge denominator, so a model can post 0.95 while most of its alerts are false.
  • PR AUC summarizes precision across recall levels. A random model scores the base rate (0.005 here, against 0.5 for ROC), so it shows how hard the problem is.
  • Operations care about one point on the curve: precision at the recall they need, or recall within the number of alerts the team can review.

In mock test A the same predictions score a ROC AUC of 0.90 and a PR AUC of 0.20.

ST 08Technical

How do you handle a heavily imbalanced target?

Show answerHide answer

In this order:

  1. Use a metric that reflects the rare class: PR AUC, recall at a fixed precision, or cost.
  2. Tune the decision threshold. This alone often does most of the work.
  3. Weight the classes (class_weight="balanced") or resample. Resample inside the training folds only, never before the split.
  4. Weighting and resampling distort predicted probabilities. Recalibrate if the scores feed a dollar calculation.
  5. Get more signal for the rare class: more history, better features.

Synthetic oversampling (SMOTE) is rarely the first lever. With enough positives, boosted trees and a tuned threshold usually match it.

ST 11Technical

Random forest versus gradient boosting: how do they differ, and which would you choose?

Show answerHide answer
  • Random forest: many deep trees, each on a bootstrap sample with a random subset of features, then averaged. The trees are independent, and averaging cuts variance. Few settings, hard to break.
  • Gradient boosting: shallow trees built one after another, each fitting the errors left so far. This cuts bias. It is usually the most accurate on tabular data, but needs tuning (learning rate, number of trees, depth) and early stopping.

Choose a forest for a fast, sturdy baseline. Choose boosting when the last points of accuracy pay for the tuning. In lending a model also has to explain its decisions, which pushes toward constrained boosting or simpler models.

In mock test B boosting beats the linear model, because price depends on age in a U shape and on an interaction that a straight-line model cannot express.

ST 12Technical · Assessment

What is data leakage? Give examples from credit or fraud modeling.

Show answerHide answer

Leakage is training on information you will not have at the moment of prediction. Validation scores look great and production results collapse.

  • A field recorded after the outcome: “chargeback filed”, “account closed”, number of collection calls.
  • Preprocessing fitted on all rows before the split: scaling, imputation, target encoding.
  • The same customer in both train and test, so the model recognizes people.
  • A random split on data that drifts over time, so the model learns from the future.
  • A customer-level aggregate that includes the transaction being scored, or later ones (question PY 07).

Prevention: build every feature as of the prediction time, keep preprocessing inside a pipeline, split by time or by customer. A score that looks too good, or one feature carrying the whole model, is the warning sign.

ST 13Technical

How would you validate a fraud model built on two years of transactions?

Show answerHide answer

Not with random k-fold. One customer’s transactions land in both train and validation, and the model trains on the future.

  • Split by time: train on earlier months, validate on later ones. Repeat with a rolling or expanding window to see how stable the result is.
  • Leave a gap between train and validation. Fraud labels arrive weeks late through chargebacks, so the most recent months are incompletely labeled.
  • Keep a final untouched period for the last check.
  • Report the metric month by month. A model that degrades steadily needs a retraining schedule.
ST 14Technical

Transaction amounts are heavily right-skewed. Can you still give a 95% confidence interval for the mean amount?

Show answerHide answer

Yes. The central limit theorem says the sample mean is approximately normal for large samples, whatever the shape of the data: mean ± 1.96 × s / √n.

  • With heavy tails the approximation needs more data. A bootstrap interval is a safe cross-check.
  • The mean of skewed data is driven by a few large values. Ask whether the median, or the mean of log amounts, answers the question better.

Define Type I error, Type II error and power for a product launch decision. What changes if you track 20 metrics?

Show answerHide answer
  • Type I: you launch a change that does nothing. Its rate is the significance level, usually 5%.
  • Type II: you drop a change that works.

ST 19Role play

A decision tree for default risk splits first on “utilization above 80%” and then on “account younger than 6 months”. Explain to a business partner how it decides, and where it can go wrong.

Show answerHide answer

The model asks a short series of yes-or-no questions. It first separates customers using more than 80% of their limit, because that one question divides defaulters from everyone else better than any other. Inside each group it asks the next most useful question. Each final group gets the default rate we saw among past customers who landed there.

Where it goes wrong:

  • A single tree is unstable. A slightly different sample can change the first question.
  • It treats 79% and 81% utilization very differently, and 81% and 99% the same.
  • Deep trees memorize. Small final groups give unreliable rates.

Forests and boosting average many trees to fix the instability. The cost is a model you can no longer read as a flowchart.

Customers who received a credit line increase went on to spend more. Did the increase cause the extra spending?

Show answerHide answer

          servicing                          =  $30.00
          acquisition   $90 / 3 years        =  $30.00
profit    $172.80 − $177.00                  =  −$4.20 a year

As specified the card roughly breaks even. Small changes flip it:

  • Cash back at 1%: +$24.
  • Defaults at 4% through a tighter approval cutoff: +$9.
  • Acquisition at $60 through campus and digital channels: +$10.

The strategic argument is lifetime value. Students become graduates with higher incomes, if the card keeps them.

Recommendation. Do not launch at scale on these numbers. Run a limited test with two reward levels, measure spend, the share who carry a balance and early delinquency, then decide on measured economics. Risks to name: the offer attracts the people who most need credit, and marketing credit to students is tightly regulated.

BC 02Case · Technical

A fraud model scores every card transaction from 0 to 1. Transactions at or above a threshold are declined. Each month there are 10 million transactions, 0.1% are fraud, a missed fraud costs $300 on average and a wrongly declined legitimate purchase costs $8. Which threshold do you choose?

Threshold Fraud caught Legitimate declined
0.9 40% 0.05%
0.7 65% 0.2%
0.5 80% 0.8%
0.3 90% 3%
Show answerHide answer

There are 10,000 frauds and 9.99 million legitimate transactions a month.

Threshold Missed fraud False declines Total cost
0.9 6,000 × $300 = $1.80M 4,995 × $8 = $0.04M $1.84M
0.7 3,500 × $300 = $1.05M 19,980 × $8 = $0.16M $1.21M
0.5 2,000 × $300 = $0.60M 79,920 × $8 = $0.64M $1.24M
0.3 1,000 × $300 = $0.30M 299,700 × $8 = $2.40M $2.70M

Choose 0.7, with 0.5 almost level.

The answer hinges on the $8. At $5 per false decline, 0.5 wins ($1.00M against $1.15M). So:

  • Ask how the $8 was estimated.
  • Scores between 0.5 and 0.7 are where the two options differ. Text those customers to confirm the purchase and do not decline outright. That keeps most of the catch for a fraction of the friction.
  • Set thresholds by amount. A missed $2,000 fraud and a missed $20 fraud are not the same cost.
BC 03Case

Should Capital One offer credit line increases to existing cardholders? To whom, and how would you find out whether it worked?

Show answerHide answer

Goal. More profit per customer without a jump in losses.

Economics, with numbers you state as assumptions. Say 30% of customers offered use the extra line. Each adds $600 of balance at 24% APR ($144 of interest) and $1,500 of purchases at 2% interchange ($30).

working
revenue per customer offered   30% × ($144 + $30)               =  $52
extra loss, existing defaulters  4.5% × $500 more lost each     =  $22.50
extra loss, new defaulters       0.5% × $1,500 balance          =   $7.50
net                              $52 − $30                      ≈  +$22 a year

Who. A long clean payment record, moderate to high use of the current line, stable or rising income, a low risk score. Avoid customers near their limit who pay only the minimum. They will use the line and are the likeliest to default.

How to test. Randomize. Give the increase to a random majority of eligible customers and hold out the rest. Compare spend, balances, delinquency at 30 and 60 days, and eventually charge-offs.

Risks. Losses arrive later than revenue, so early results flatter the program. Watch early delinquency as the leading signal. Affordability rules also limit who can be offered more credit.

BC 04Case

A city bus route breaks even. It carries 1,200 riders a day at a $2 fare. Four buses run all day, and each costs $600 a day ($450 for the driver, $150 for fuel and maintenance). How would you make it profitable?

Show answerHide answer

Capital One’s own case advice uses a bus route as its example, so this style is worth one rehearsal.

working
profit = riders × fare − buses × cost per bus
       = 1,200 × $2 − 4 × $600
       = $2,400 − $2,400 = $0

The levers are price, ridership, cost and other revenue.

  • Fare to $2.50, assuming 10% of riders leave: 1,080 × $2.50 = $2,700. Gain $300 a day.
  • One bus off the road in the midday lull, saving half a bus-day ($300) and assuming 5% of riders leave ($120): gain $180 a day.
  • Advertising on buses and shelters: small, low risk.
  • More riders through a better timetable or employer passes: slower and uncertain.

Recommendation. Test the fare increase first. It is the largest gain and easy to reverse. Check the rider-loss assumption on a few routes before rolling out, and look at who leaves, because a public route also has a service goal. Then trim midday frequency using rider counts by hour.

What the interviewer looks for: a structure before the numbers, clean arithmetic, a stated assumption for every number you invent, and a recommendation.

BC 05Case · Technical

Marketing mails 1 million card offers at $0.50 each. 1% respond, 60% of responders are approved, and an approved account is worth $200. A response model ranks prospects: the top 30% by score contain 70% of the responders. Should you mail only the top 30%?

Show answerHide answer
Mail everyone Mail the top 30%
Mail cost $500,000 $150,000
Responders 10,000 7,000
Approved accounts 6,000 4,200
Value $1,200,000 $840,000
Profit $700,000 $690,000

Mailing only the top 30% earns slightly less in total, at a far better return on spend. The bottom 70% of the list returns $360,000 for $350,000 of mail.

The better question is where to stop. A mail piece pays for itself when:

working
response rate × 60% × $200 ≥ $0.50     →     response rate ≥ 0.42%

The bottom 70% averages 3,000 / 700,000 = 0.43%, barely above the line, so its weaker half is below it.

Recommendation. Mail down the ranking until the expected response rate reaches 0.42%, then stop.

Two cautions to raise. People who respond to credit offers tend to be riskier than those who do not, so approval rate and account value probably fall as you go down the list. And the model should be checked on a randomly mailed sample, or you only ever learn about people you chose to mail.

BC 06Case · Technical

Calls to the customer service center rose 20% this quarter. A call costs about $6 and there are 1 million calls a month. Diagnose the increase and say what a data scientist could do about it.

Show answerHide answer

Clarify. Is it total calls or calls per active account? If accounts grew 20%, nothing is wrong.

Break it down. By call reason, product, customer tenure, what the customer did just before calling (app, website, a mailed letter) and by week. A rise spread evenly suggests growth or season. A rise concentrated in one reason points to a cause: a new fee, a confusing statement redesign, an app outage, a wave of fraud alerts, a product launch.

Data. Call logs with reason codes, phone menu paths, app and web activity before the call, account events such as a new card, a payment due date or a declined transaction.

What data science adds.

  • Predict who will call in the next few days and why, and reach them first with a message or an app prompt.
  • Route each call to the right team first time using predicted intent.
  • Forecast volume for staffing.

Size it. 1 million calls × $6 = $6M a month. Deflecting 5% saves $300,000 a month.

Test it. Randomize the proactive message. Compare call rates and satisfaction, and check that customers are not simply pushed to another channel with the problem unsolved.

BC 07Technical · Case

Walk me through how you would build a credit card fraud detection model, end to end.

Show answerHide answer

Candidates report this question in several forms. Give it a spine of eight steps.

  1. Target and decision. Fraud confirmed by a chargeback or a customer report, per transaction. The model has to choose between approve, challenge and decline within milliseconds, so every feature must be available that fast.
  2. Data and labels. Labels arrive weeks late, and declined transactions never get one. Train on a period old enough to be fully labeled.
  3. Features, all as of the transaction time. The amount against the customer’s usual amounts. The count and value of transactions in the last hour and day. Merchant type and whether it is new for this customer. Distance from the last transaction. A change of device or address. Account age. Time of day.
  4. Split by time, with a gap for late labels (ST 13).
  5. Model. Logistic regression as a baseline, then gradient boosting. Handle the imbalance through weights and thresholds (ST 08).
  6. Evaluate in business terms. PR AUC, recall at the false alarm rate the business accepts, dollars of fraud caught per false decline. Check new accounts, online purchases and large amounts separately.
  7. Thresholds by cost, with a challenge band in the middle (BC 02).
  8. Deploy and monitor. Score distribution, feature drift, alert volume, and realized fraud once labels arrive. Fraudsters adapt, so plan regular retraining and keep rules for new attack patterns.

Close by naming the two weak points: label delay, and the feedback loop created by declining transactions.

BC 08Case · Technical

The approval rate for card applications fell from 42% to 37% in a week. Last week: 60,000 organic applications approved at 50% and 40,000 affiliate applications approved at 30%. This week: 50,000 organic at 50% and 65,000 affiliate at 27%. What happened?

Show answerHide answer

Check the totals first.

working
last week   (30,000 + 12,000) / 100,000 = 42.0%
this week   (25,000 + 17,550) / 115,000 = 37.0%

A blended rate moves for two reasons: the mix of applicants, and the rate inside each group.

working
this week's mix at last week's rates   (25,000 + 19,500) / 115,000 = 38.7%
mix effect                             42.0 − 38.7 = 3.3 points
rate effect                            38.7 − 37.0 = 1.7 points
  • Mix. Affiliate applications went from 40% to 57% of volume, and that channel approves at a lower rate. This explains 3.3 of the 5 points.
  • Rate. Affiliate approvals slipped from 30% to 27%, which explains the other 1.7. Organic did not change.

Nothing broke in underwriting. An affiliate partner sent a surge of applicants, and they are weaker than that channel’s usual applicants.

Next. Find the partner and campaign. Compare the credit quality and early fraud signals of the new applicants. Check the cost per approved account for that partner. Recommend judging channels on approved accounts and their quality, not on application volume.

Before any of this, spend thirty seconds confirming that the metric definition and the data feed did not change.

Behavioral and job fit

Capital One describes its behavioral questions as “tell me about a time” questions, and recruiters for its AI teams point candidates to the STAR format: situation, task, action, result. Aim for two minutes. Spend 20 seconds on the situation and task, 80 seconds on what you did, and 20 seconds on the result and what you learned. Say “I” for your own work.

The posting names four traits: intellectually curious, a builder, an experimental scientist, a communicator. Prepare a story for each. The answers below are checklists, because the content has to be yours.

BH 01Job fit

Tell me about yourself.

Show answerHide answer

Ninety seconds, three parts.

  1. Now. Your program, your focus, one line on your strongest project.
  2. Before. The one or two experiences that led here, each with a result.
  3. Next. Why data science at a company where models make decisions about real customers, and why this internship.

Check yourself: no life story, no reading the resume in order, one number somewhere, and an ending that explains why you are in this interview.

BH 02Job fit

Why Capital One, and why this internship?

Show answerHide answer

Three ingredients, each specific.

  • Something true about the company that matters to you. Worth researching: its history of using data and experiments to make credit decisions, its move to the public cloud, and its open-source data science tools. Read one recent post from its tech blog and be ready to say what interested you.
  • The work. The posting describes building models on real business data and explaining results to customers and leaders. Connect that to something you have done.
  • The ten weeks. What you want to learn, and what you would contribute.

Avoid “it is a great company”, pay, and anything you could say about any bank.

BH 03Technical · Job fit

Walk me through a data science project you are proud of.

Show answerHide answer

Expect five minutes and many follow-ups. Recruiters for Capital One’s AI teams say they want the why behind each choice and a clear line around what you personally did.

  1. The question, and why it mattered. One sentence each.
  2. The data: size, source, and the worst problem with it.
  3. What you tried, including what failed.
  4. How you validated the result, and the number.
  5. What you would do differently.

Follow-ups to rehearse:

  • Why that model and not a simpler one?
  • Why that metric?
  • How do you know nothing leaked?
  • What was the baseline?
  • What did the result change?
BH 04Behavioral

Tell me about a time you explained a technical result to someone without a technical background.

Show answerHide answer

Trait: communicator. Strong answers show that you changed the explanation for the audience and that they acted on it.

  • Situation. Who they were and what they had to decide.
  • Action. What you left out, the comparison or picture you used, how you checked they followed.
  • Result. The decision they made.

A sample, to show the level of detail and not to copy:

In my capstone, the sponsor’s operations manager had to decide whether to act on our churn model. In the first meeting I showed an ROC curve and lost her. For the second I brought one slide: of the 100 customers the model ranks riskiest, 38 leave within a quarter, against 9 of a random 100. I asked what her team could do with a list of 100 names a week. She piloted retention calls on that list the next month.

BH 05Behavioral

Tell me about a time an analysis or experiment of yours failed, or you were wrong.

Show answerHide answer

Traits: experimental scientist, and what Capital One calls being vulnerable. They want to hear that you noticed, said so, and changed something.

  • Pick a real failure with stakes, not a success in disguise.
  • Say plainly what you got wrong and how you found out.
  • Spend most of the answer on what you did next and the habit you changed.

Good material: a model whose validation score collapsed on new data, a leak you found in your own features, a hypothesis the data rejected.

BH 06Behavioral

Tell me about a time you disagreed with a teammate or an advisor. What happened?

Show answerHide answer

They are checking that you can disagree with evidence and stay respectful.

  • State both positions fairly. The other person should sound reasonable.
  • Show how you tested the disagreement: data, a small experiment, a third opinion.
  • Say what was decided and that you committed to it, including when your view lost.

Avoid stories where the other person was simply wrong, and stories with no resolution.

BH 07Behavioral

Tell me about a time you fixed or built something nobody asked you to.

Show answerHide answer

Trait: a builder with a sense of ownership.

  • What you noticed and why it bothered you.
  • What you built and what it cost you in time.
  • Who used it afterwards and what changed.

Good material: a script that replaced a manual step for your lab, a data check that caught errors, documentation that got new teammates started faster.

BH 08Behavioral

Tell me about a time you had to make a decision with incomplete or messy data.

Show answerHide answer

They are listening for judgment: what you checked, what you assumed, and how you limited the damage if you were wrong.

  • What was missing or unreliable, and why waiting was not an option.
  • How you sized the uncertainty: a quick sensitivity check, a best case and a worst case.
  • The decision, how you flagged the caveats, and whether it held up.
BH 09Behavioral

Tell me about a time doing the right thing was the harder option.

Show answerHide answer

This maps to one of the company’s two stated values. Typical student material:

  • You found an error in results you had already presented and corrected the record.
  • You reported a leak or a bug that made your own numbers look worse.
  • You turned down a shortcut that used data you were not supposed to use.

Say what the easy option was, what it would have cost someone else, and what you did.

BH 10Behavioral

Tell me about a time you had to learn a new tool or method quickly.

Show answerHide answer

Trait: intellectually curious.

  • Why you needed it and how little time you had.
  • How you learned: the smallest working example first, then the documentation, then asking someone.
  • What you delivered with it, and whether you still use it.

Add what you are learning now. Recruiters for Capital One’s AI teams say they look for people who keep up with new techniques.

Do you have any questions for me?

Show answerHide answer

Always yes. Bring six and ask two or three in each interview.

  • What does a typical intern project look like, and what did last summer’s interns deliver?
  • How does a model here get from a notebook to a decision that affects customers?
  • How do data scientists and business analysts split the work on your team?
  • What is the hardest part of working with your data?

Skip anything answered on the careers site, and keep pay and logistics for the recruiter.

Case

A business situation with some numbers. You talk through it and finish with a recommendation.

Capital One’s advice, in short: Official

  • There is no single right answer. End with what the business should do and why.
  • Say your reasoning as you go, and support it with the data you are given.
  • Use plain language, as if explaining to someone from another field.
  • Stay on the case. It is not the moment to talk about your resume.
  • Take notes and ask questions.

A method that works:

  1. Restate the goal in one sentence. Ask two or three questions: what counts as success, over what period, any limits.
  2. Lay out the structure before you calculate. For most cases that is profit = revenue − cost, each split into its drivers.
  3. Do the arithmetic out loud. Round sensibly, write every number down, keep the units.
  4. Say what each number means for the decision.
  5. Recommend. Name the two biggest risks and the first thing you would test.
  6. Update when pushed. If the interviewer changes an assumption, rework the answer. Recruiters for Capital One’s AI teams say they watch how candidates use feedback in the moment. Official

Arithmetic to have ready: percentage changes, break-even (fixed cost ÷ margin per unit), expected value (probability × amount), and scaling a per-customer figure to a whole portfolio.

A card earns interest on balances, interchange on purchases, and fees. It pays for credit losses, rewards, funding, servicing and marketing. Cases BC 01, BC 03 and BC 05 use this.

Technical

A conversation about statistics and machine learning, often anchored on your own project or on the assessment you submitted. Reported

  • Be ready to defend every choice in your assessment and in each project on your resume: why this model, this metric, this validation.
  • Expect “what would you do with more time?” and “how would this fail in production?”
  • If you do not know, say so, then reason from what you do know. A confident guess is the worst option.

Role play

Candidates describe being handed a slide, a chart or a model output about a business problem, given a few minutes to read it, and then explaining it to an interviewer who plays a non-technical colleague. Regression output and decision trees have both come up. Reported

A structure for the explanation:

  1. The headline. What the analysis says, in one sentence.
  2. The evidence. The one or two numbers that carry it.
  3. How sure you are, and what could make it wrong.
  4. What you would do next.

Translate every technical term, pause to check they are with you, and welcome the pushback. If they ask “so should we do it?”, say yes or no first and then give the reason.
